# @jeopardy/web

The SvelteKit 3 app Worker: every UI surface (editor, host console, board display, phone buzzer - all future milestones), later the REST API with D1/R2. Since M3 it is also the SINGLE ORIGIN for realtime (docs/decisions/2026-08-13-single-origin-binding.md): `POST /api/rooms` creates rooms (server-allocated code + host token) and `/room/[code]/ws` forwards WebSocket upgrades to `GameRoomDO` over the cross-script `GAME_ROOM` binding - the upgrade passes straight through the Kit endpoint path (proof + canary: `scripts/prove-single-origin.mjs`; verdict recorded in the decision doc's addendum).

- SvelteKit 3 prerelease: config lives in `vite.config.ts` (no svelte.config.js), `#lib` replaces `$lib`, env vars are declared in `src/env.ts` - the full SK2-vs-SK3 list: docs/decisions/2026-08-13-m0-version-pins.md.
- PWA skeleton: `static/manifest.webmanifest` + `src/service-worker/` (network-first navigations, precached immutable assets, no skipWaiting - docs/decisions/2026-08-13-pwa.md). No install prompts anywhere.
- `/dev/rooms` is the room instrument panel (create/delete rooms, connect and join through the single origin, DO inspector, auto-refreshing lobby, refusal probes - run it with `pnpm dev:rooms`, docs/DEVELOPMENT.md); `/dev/theme` is the theme gallery (live preset switcher over the token contract - docs/design/theming.md); `/dev/hotseat` plays a full game against `@jeopardy/engine` with one keyboard and no server (the M2 exit-criteria proof; game material from `src/lib/hotseat/sample-game.ts`, a real parsed game-definition document). `/dev/*` routes never get linked from product UI.
- Play surfaces (M4, mock-first): `/room/[code]` (A2 join -> A3 lobby -> A4 buzzer), `/room/[code]/display` (projector: QR title screen, board, clue card, winner), `/room/[code]/host` (C4 console with mirror mode `?mirror` and the dev sim panel). All three sit on the room-store seam in `src/lib/room/` - the local-sim store (engine + fixtures/) is the default until the M3 reconcile flips `create-room-store.ts` to the ws store. Contract + reconcile gap list: docs/design/surfaces.md.
- Theming: token contract in `src/lib/theme/tokens.css`, presets + document-to-CSS mapping alongside it, self-hosted fonts in `static/fonts/` (licensing there). Reference: docs/design/theming.md.
- Avatars: baked sprites in `static/avatars/` (licensing there) + the generated manifest and presentational picker/chip components in `src/lib/avatars/` - all written by `tools/avatar-bake` (re-bake instructions in its README); the manifest gate test keeps sprites, manifest, and theme preset accents in sync.
- `pnpm check` runs svelte-check plus a separate `tsc -p src/service-worker` (WebWorker libs).
