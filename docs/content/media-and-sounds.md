## 5. Per-file license verification checklist (run before bundling anything into the app)

For **every** image/sound that makes the final cut:

1. **Re-open the source page** on event-prep day (links above). Freesound and Commons items occasionally get relicensed, taken down, or replaced by uploaders.
2. **Read the license line on the page itself** — never trust this doc or a search-result filter as final. For Commons: the "Licensing" section of the file page. For Freesound: the license link under the waveform. For Pixabay: the "Free for use" badge + Content License link on the track page.
3. **Commons-specific:** check the _file page_ license, not the article; confirm the author field matches what we recorded (a differing author = the file was replaced — re-evaluate). For NPS/USGS files, confirm the credit line actually says NPS/USGS (occasional third-party images appear in federal galleries — pool §3 warning).
4. **Screenshot the license section** (or save the page as PDF) into `docs/content/licenses/` — proof-of-license at download time.
5. **Record a credits row** per file: filename in app bundle · source URL · author · license · date verified. Even CC0 files get a row (courtesy + audit trail). CC BY / CC BY-SA files additionally go on the event credits slide.
6. **Download the original** (Commons "Original file" link; Freesound download button — requires a free account; Pixabay download button) — never hotlink at the event; Wi-Fi is a failure mode (see manual-mode directive).
7. **Media QA:** images ≥1920 px long edge and legible from the back of the room; sounds trimmed ≤1.5 s (buzz-ins) / ≤3 s (cues), loudness-normalized (target ≈ −16 LUFS), exported to one format (OGG or MP3) at one sample rate.
   7b. **Standardized onset (owner directive 2026-08-13):** raw files carry wildly different leading silence, which for buzz-ins is both perceived latency and a fairness problem (one team's sound "reacting" later than another's). Every bundled sound is processed to a **uniform onset**: leading silence trimmed so audible energy begins at a fixed ~10 ms into the file - identical across the whole pack, never zero (a 2-5 ms micro fade-in stays, preventing click/pop artifacts on instant playback). Verify with a batch waveform check (e.g. ffmpeg `silencedetect` / peak scan): first sample above -40 dBFS must land in the 8-15 ms window for every file. Playback side (M4): sounds are pre-decoded into Web Audio buffers at lobby load and triggered via AudioContext, not `<audio>` elements - file onset is then the only delay variable, which this step makes constant.
8. **Attribution audit:** if ANY CC BY / CC BY-SA file ships, the credits slide is mandatory — verify each attribution string follows the TASL pattern (Title, Author, Source, License).

### Lobby music - the signature track (owner directive 2026-08-13)

Kahoot's lobby theme proves the pattern: one upbeat, anticipation-building track that plays in EVERY lobby, always the same - identity through repetition. Requirements for ours:

- **One track, never rotated** (unlike think music). It becomes the product's sound. Theme sound-sets may eventually offer variants, but the default is sacred.
- **Character**: upbeat, playful tension, builds without wearing out; survives 5+ minutes of looping while a room fills up.
- **Seamless loop** - engineered loop points, no audible seam.
- **License**: CC0 strongly preferred (bundle policy); CC-BY acceptable ONLY if the attribution story is clean (in-app credits screen), since this ships in every deploy.
- Round-2 sourcing hunts candidates; a genuinely iconic option may also come from commissioning/generating an original 8-16 bar loop later - candidates first, then judge.
