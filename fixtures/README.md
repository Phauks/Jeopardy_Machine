# fixtures/

The canonical dummy dataset for data-flow testing (owner request 2026-08-13). These files are versioned test DATA, deliberately outside any package's `src` - apps and packages read them in tests and dev tooling, never bundle them as features. Every clue is hand-written fiction (environment + gaming flavor, zero real-world trivia claims), so nothing here can ever be mistaken for real event content.

Validation lives in `packages/protocol/src/fixtures-dataset.test.ts`: every portable document below parses through `parsePortableDocument` (the one public entry point), round-trips stably (parse -> serialize -> parse), and preserves its `ext` bags; the roster is structurally checked against a local zod shape there.

## The rule: fixtures migrate, they are never silently regenerated

When a document format bumps its schema version, these files are updated **by running the registered migration** (the same path a user's old file takes) and committing the result in the same PR as the bump - never by regenerating them from scratch. A regenerated fixture would silently stop proving that old files survive; a migrated fixture proves exactly that. Hand-edits are fine for content (they are hand-written data), but a format bump without the migration applied here fails the fixtures test and must not land.

Two derived values pin the pack/game pair together and must move with any pack edit:

- `dummy-game.game.json` -> `body.content.sha256` is the sha256 of the exact bytes of `dummy-pack.pack.json` (this dataset's stand-in for the "canonical JSON" drift check, which the format leaves unspecified). Recompute after any pack edit (`sha256sum fixtures/dummy-pack.pack.json`); the fixtures test enforces the match.
- `dummy-game.game.json` -> `body.content.packId` matches the pack's `ext["com.example.fixtures"].libraryId`. The content-pack format has no intrinsic id field (library ids are assigned at import), so the fixtures carry the pairing in the pack's `ext` bag.

## Conventions inside the data

- Ids are hand-crafted but valid UUIDv7s under the `0198f00d-...` prefix, with readable suffixes: item `...0111` = round 1, category 1, row 1; `...0999` = the final; block `0001` = pack items, `0002` = prompt media, `0003` = answer media, `0004` = mini-pack items, `0005` = theme media.
- All `sha256` values on media assets are dummy hex (the `feedfeed...` pattern + id suffix); no media bytes exist. Remote URLs point at `media.example.com` and do not resolve - by design, so nothing ever fetches them outside a mocked test.
- `ext` bags use `com.example.*` keys only (obviously-dummy reverse-domain names).
